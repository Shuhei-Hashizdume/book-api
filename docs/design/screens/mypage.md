既存の基本仕様20項目、最終設計15項目の確定事項を引き継ぎ、今回決定したログアウト機能を追加する。

## 4. プロフィール

### 4.1 表示内容

- アバター
- ユーザー名
- 自己紹介（未設定なら省略）
- フォロー中の人数
- フォロワーの人数
- プロフィール編集ボタン

### 4.2 プロフィール編集

編集画面の要素順：

1. アバターと変更ボタン
2. ユーザー名
3. 自己紹介
4. 保存ボタン

#### ユーザー名

- 1〜30文字
- 日本語・英数字・アンダースコア
- ユーザー間で一意
- 変更回数の制限なし
- `user_id` は変更しない
- 重複などのエラーは入力欄の直下に表示

#### 自己紹介

- 任意
- 最大200文字
- 複数行入力
- リアルタイム文字数カウンター
- 空欄ならプロフィールでは非表示

#### アバター

- 動物アバター12種類
- 本モチーフのデフォルトアバター1種類
- 合計13種類
- 画像アップロードなし
- 選択画面は4列×3行

#### 保存フロー

```text
プロフィール編集
      │
      ├── アバター選択
      │      └── 仮選択して戻る
      │
      ├── ユーザー名変更
      ├── 自己紹介変更
      │
      ▼
    [保存]
      │
      ▼
まとめてDB更新
      │
      ▼
  マイページ
```

アバター選択だけではDBを更新しない。

保存中は入力欄と保存ボタンを無効化し、二重送信を防ぐ。

保存失敗時は編集内容を保持する。

未保存の変更がある状態で離脱する場合は、「編集を続ける」「破棄して戻る」の確認を表示する。

## 6. 読んだ本の冊数

プロフィールの下に、次の情報のみ表示する。

**📚 読んだ本 ○冊**

未読・読んでる・読みたいの冊数は表示しない。

### 6.1 集計定義

本仕様の「読んだ本」は、現在の読書状態が「読んだ」である本の重複なし件数を意味する。

### 6.2 バックエンド上の注意事項

過去の調査では、`services/profile.py` は `CompletedBook` テーブルの件数を集計していた。

一方、読書状態は `UserBook.status` で管理されている。

`routers/user_books.py` では「読んだ」へ変更した際に `CompletedBook` を作成するが、別の状態に戻した際に過去の `CompletedBook` を削除する処理は確認できなかった。

そのため、現在「読んだ」状態の冊数と、過去に読んだことのある本の累計冊数が一致しない可能性がある。

既存の `CompletedBook` の用途を維持しつつ、現在の読書状態に基づいた正しい集計方法を使用する必要がある。

## 7. 読書記録タブ

### 7.1 表示内容

- 書籍の表紙
- タイトル
- 著者
- 読書状態

読書状態は以下の3種類。

| 表示名   | 既存Enum値     |
| -------- | -------------- |
| 未読     | `want_to_read` |
| 読んでる | `reading`      |
| 読んだ   | `completed`    |

既存の `ReadingStatus` を再利用する。

「読みたい」は第4の読書状態ではなく、一覧の絞り込み条件とする。

### 7.2 絞り込み

| 条件       | 対象                           |
| ---------- | ------------------------------ |
| すべての本 | 登録済みの全書籍               |
| 未読       | 未読状態                       |
| 読んでる   | 読書中状態                     |
| 読んだ     | 読了状態                       |
| 読みたい   | 読みたい本リストに登録された本 |

#### 既存実装との差分

過去の調査では、`UserBook` は読書状態と優先度を同じレコードに保持していた。

また、`GET /users/me/books` の `list_type` は、`want_to_read` と `completed` の2分類だった。

現行実装では、`want_to_read` 側は「読んだ以外の状態」を取得するため、独立した読みたいリストへの登録有無を表すものではない。

したがって、読みたいリストへの登録状態を読書状態から独立して識別する必要がある。

既存の `UserBook.priority` は必須であるため、その有無だけでは読みたいリストへの登録状態を判定できない。

### 7.3 並び順

新しく登録した順。

読書状態を変更しても並び順を変えない。

過去の調査では `UserBook` に登録日時カラムが存在しなかった。

必要に応じて `created_at` の追加を検討する。

ただし、過去の登録日時は既存DBから正確に復元できない可能性があるため、既存データの扱いは別途確定する。

### 7.4 ページネーション

- 初回20冊
- 追加20冊
- スクロールで自動取得
- カーソル方式を基本とする
- 取得済みデータを重複表示しない

### 7.5 書籍詳細への遷移

一覧カードをタップすると書籍詳細へ移動する。

読書状態は書籍詳細で変更する。

戻った際は、元のタブ・絞り込み・スクロール位置を保持し、変更結果を反映する。

## 11. データ更新・削除時の反映

- 読書状態変更：状態ラベル・絞り込み結果・冊数を更新
- 投稿編集：カード内容を更新
- 投稿削除：カードを除外
- 公開状態変更：公開・非公開ラベルを更新

## 13. ログアウト機能【今回追加】

### 13.1 概要

マイページからログアウトできる機能を提供する。

ログアウト操作は、マイページ右上の「⋮」メニューから行う。

独立した設定画面 `settings.md` は作成しない。

### 13.2 ログアウトメニューの配置

- マイページのタイトル右側に「⋮」メニューボタンを配置する。
- メニューボタンを押すと操作メニューが開く。
- メニュー内に「ログアウト」を表示する。
- マイページ下部にはログアウトボタンを配置しない。
- PC・スマートフォンともに同じ操作方法とする。

#### 画面イメージ

```text
┌────────────────────────────┐
│ マイページ              ⋮ │
├────────────────────────────┤
│                       ┌──────────────┐
│                       │ ログアウト   │
│                       └──────────────┘
│                            │
│      🐻 ユーザー名         │
│      自己紹介              │
│                            │
│   [ プロフィール編集 ]     │
│                            │
│ [読書記録][読了投稿][気づき]│
│                            │
└────────────────────────────┘
```

### 13.3 ログアウト確認ダイアログ

メニュー内の「ログアウト」を選択した場合、すぐにはログアウト処理を開始せず、確認ダイアログを表示する。

#### 表示内容

**メッセージ**

ログアウトしますか？

**ボタン**

- キャンセル
- ログアウト

#### 画面イメージ

```text
┌────────────────────────────┐
│ マイページ              ⋮ │
│                            │
│  ┌──────────────────────┐  │
│  │                      │  │
│  │ ログアウトしますか？ │  │
│  │                      │  │
│  │ [キャンセル]         │  │
│  │ [ログアウト]         │  │
│  │                      │  │
│  └──────────────────────┘  │
│                            │
└────────────────────────────┘
```

#### ボタンの動作

| 操作       | 動作                               |
| ---------- | ---------------------------------- |
| キャンセル | ダイアログを閉じ、マイページに戻る |
| ログアウト | ログアウト処理を開始する           |

ダイアログ表示中は、背後のマイページを誤操作しないようにする。

### 13.4 ログアウト処理中

- ログアウト処理中は、確認ダイアログの「ログアウト」ボタンを連続操作できないようにする。
- 同じログアウト処理が重複実行されないようにする。
- ログアウト完了前にWelcome画面へ遷移しない。

### 13.5 ログアウト成功時

ログアウト処理が正常に完了した場合、認証済み状態を終了してWelcome画面へ遷移する。

**遷移先：`welcome.md`**

#### 画面遷移

```text
マイページ
    │
    ▼
右上の「⋮」を押す
    │
    ▼
「ログアウト」を選択
    │
    ▼
┌──────────────────────────┐
│ ログアウトしますか？     │
│                          │
│ [キャンセル]             │
│ [ログアウト]             │
└──────────────────────────┘
    │
    ▼
ログアウト処理
    │
    ▼
ログアウト成功
    │
    ▼
Welcome画面（welcome.md）
```

#### 認証状態の扱い

- ログアウト成功後は認証済み状態を終了する。
- 認証情報は、採用している認証方式に従って無効化または破棄する。
- ログアウト後に認証必須画面へアクセスした場合は、既存の認証・アクセス制御仕様に従う。
- ブラウザの戻る操作によって、ログアウト前の認証必須コンテンツを再表示できないようにする。

### 13.6 ログアウト失敗時

ログアウト処理が完了していないことを確認できた場合は、Welcome画面へ遷移しない。

確認ダイアログを閉じ、マイページ上にエラーメッセージを表示する。

#### エラーメッセージ

**ログアウトできませんでした。もう一度お試しください。**

#### 動作

- マイページに留まる。
- ログアウト成功として扱わない。
- ログイン状態を維持する。
- 再度「⋮」メニューからログアウトを試せるようにする。

通信が途切れるなどしてログアウトの成否が不明な場合は、認証状態を再確認する。

成否が未確認のまま、ログアウト成功または失敗と断定しない。

### 13.7 PC・スマートフォンでの表示

- PC・スマートフォンともにマイページ右上から操作する。
- メニュー項目とボタンはタップしやすいサイズを確保する。
- 確認ダイアログは画面幅に合わせて調整する。
- 文字サイズを拡大しても、メッセージやボタンが重ならないようにする。
- ダイアログのボタンはキーボードでも操作できるようにする。
