# BookAPP ログイン画面設計

作成日：2026-10-19  
更新日：2026-10-20  
状態：画面の基本動作・表示文言・認証後の復帰方針・「戻る」操作は確定。Cookie認証は未実装。視覚デザインと一部実装詳細は未決定。

## 1. 目的・関連文書

未ログインの利用者がメールアドレスとパスワードで認証し、認証を開始した経緯に応じた画面へ進むための画面。

- ウェルカム画面からログインした場合は、成功後にホームへ進む。
- 本棚など認証必須画面へのアクセスをきっかけにログインした場合は、成功後に元々アクセスしようとした画面へ進む。
- `GET /users/me` で既にログイン済みと確認できた場合は、フォームを表示せず、上記と同じ遷移先へ進む。

関連文書：[ウェルカム](welcome.md)、[新規登録](signup.md)、[ホーム](home.md)、[共通認証フロー](../flows/authentication.md)。

共通の認証方式・期限・認証確認・ログアウト・セキュリティは共通認証フローを正本とする。本書はログイン画面固有の表示と操作を定義する。

## 2. 確定した表示・操作

- ヘッダー・フッターなし。左上に「← 戻る」を表示する。
- 「← 戻る」はブラウザ履歴に依存せず、必ずウェルカム画面へ移動する。その際、保持している元の保護画面への復帰予定を解除する。直接URLアクセス時も同じ。
- 中央フォームに「ログイン」、上部通知領域、メールアドレス、パスワード、ログインボタン、下部の新規登録リンクを縦に配置する。
- 入力は `email` / `password` のみ。パスワードは初期状態で伏字とし、👁ボタンで表示・非表示を切り替える。切替操作では値を変更せず、送信もしない。
- 送信開始時にパスワード表示を伏字へ戻す。通常ボタンは「ログイン」、送信中は無効化し「ログイン中...」を表示する。Enterキーを含む重複送信を防止する。
- 入力エラーは各欄直下、認証失敗・通信障害・期限切れ通知はフォーム上部に表示する。初期表示では入力エラーを出さない。
- 下部の「新規登録」リンクは新規登録画面へ移動する。認証必須画面からの復帰予定がある場合、登録後の認証成功時にも同じ復帰先を利用する。登録画面の「戻る」操作の扱いは `signup.md` と整合させる。
- パスワード再設定リンクは表示しない。下部の補助文言は未決定。
- 認証確認中はフォームを表示・操作させず、共通ローディングを使用する。

## 4. 遷移と API

### 4.1 画面入場とログイン

```text
ウェルカム／新規登録からのログインリンク／直接アクセス／
認証必須画面からの誘導／期限切れ
      |
      v
共通ローディング → GET /users/me
      |
      +-- 200 → 認証済み → 復帰先があれば目的画面、なければホーム
      |
      +-- 401 → ログインフォーム
      |              （期限切れと識別できた場合は上部通知）
      |
      +-- 確認不能 → 共通の確認失敗画面 → 再試行

ログインフォーム
      |
      +-- blur → 対象欄を検証
      |
      +-- 送信 → 全欄を検証
                     |
                     +-- 不正 → 欄直下にエラー、API呼び出しなし
                     |
                     +-- 正常 → POST /users/login
                                     |
                                     +-- 200 → 復帰先があれば目的画面
                                     |           なければホーム
                                     +-- 401 → 上部に認証失敗、password消去
                                     +-- 422 → 該当欄に検証エラー
                                     +-- 通信失敗／15秒 → 上部に通信エラー

「← 戻る」→ 復帰先を解除 → ウェルカム
「新規登録」→ 復帰先を引き継ぐ → 新規登録画面
```

### 4.2 認証後の復帰先

| ログイン開始の経緯 | 認証成功後 |
|---|---|
| ウェルカムからログイン | ホーム |
| ログイン画面への直接アクセス | ホーム |
| 保護画面からログインへ誘導 | 元々アクセスしようとした保護画面 |
| 保護画面からログインへ誘導後、新規登録へ切り替え | 登録・自動ログイン成功後に元々アクセスしようとした保護画面 |
| ログイン画面で「← 戻る」を押した後、ウェルカムから改めてログイン | ホーム（以前の復帰先は解除済み） |

**確定事項：**「← 戻る」でウェルカムへ移動した時点で、以前の保護画面への復帰予定を解除する（A案）。ログイン成功時の復帰先は、アプリ内で許可された画面に限定する。保持方法、URL、履歴方式は未決定。

### 4.3 API契約

| API | 現行契約 | 設計上の利用・差分 |
|---|---|---|
| `GET /users/me` | Bearer認証。200で`id,username`、認証拒否401 | 入場時に確認。認証済みなら復帰先またはホームへ。将来はCookie認証に対応する |
| `POST /users/login` | JSONの`email,password`。200で`access_token,token_type: bearer`、401、422 | 将来はサーバーがHttpOnly Cookieを設定。成功後は復帰先またはホームへ |

ログインAPIには、リクエストごとに送信開始から15秒のクライアント側タイムアウトを適用する。タイムアウトはサーバーでのログイン処理やCookie設定が完了していないことを保証しないため、自動再送信しない。

## 5. 入力検証

| 項目 | 現行`UserLogin`に合わせる制約 |
|---|---|
| `email` | 必須、有効なメールアドレス形式、255文字以下 |
| `password` | 必須、1〜128文字。登録時の8文字以上という制約をログインへ追加しない |

- blur（入力欄からフォーカスが外れた時）にその欄を、送信時に全欄を検証する。
- 入力不正ならAPIを呼ばない。
- エラーは該当欄の直下へ表示し、修正時にその欄の既存エラーを解除する。解除しただけで検証済みとはせず、次のblur／送信時に再検証する。
- 初期エラーは表示しない。検証エラー時はemail/passwordの入力値を保持する。
- APIの422も既知の入力欄へ対応づける。フロントのメール形式判定とAPIの`EmailStr`の完全一致は前提にせず、API側でも最終検証する。
- パスワードは自動トリミング・整形しない。
- 各エラー文言、優先順位、文字数計算、メール正規化の詳細は未決定。

## 6. 状態ごとの表示・保持・再試行

| 状態 | 表示・操作 | 入力値 |
|---|---|---|
| 認証確認中 | 共通画面「BookAPP」「読み込み中...」。フォーム操作不可 | フォームをまだ表示しない |
| 認証確認の通信失敗 | 「ログイン状態を確認できませんでした。」「再試行する」。未ログインと断定しない | フォームへ進めない |
| 未ログイン確認後 | 空のフォーム、入力エラーなし | 空欄 |
| 入力エラー | 各欄直下。修正・再送信可 | 両方保持 |
| 送信中 | パスワード伏字、無効ボタン「ログイン中...」 | 送信値はその試行の値を使う |
| ログイン401 | 上部「メールアドレスまたはパスワードが正しくありません。」。再試行可 | email保持、password消去 |
| 通信失敗・タイムアウト | 上部「通信エラーが発生しました。時間をおいて再度お試しください。」。再試行可 | email/password保持、伏字 |
| ログイン422 | 該当欄直下にエラー。修正・再試行可 | 両方保持 |
| ログイン成功 | 復帰先があれば目的画面、なければホームへ | 画面離脱後の入力復元は未確定 |
| 期限切れと識別できた | 上部「ログインの有効期限が切れました。もう一度ログインしてください。」 | 初回未ログインとは区別 |

ログインAPIの401を、本人確認APIの401や期限切れと混同しない。期限切れの識別方法は共通認証フローの未決定事項とする。本人確認が5xx等で失敗した場合も、認証確認失敗画面から再試行できるようにする。

ログインAPIの5xx・403・想定外応答の通知文言は未決定であり、資格情報不一致と断定しない。フォーム上部通知の修正時・再試行時の解除条件も未決定とする。

## 7. セキュリティと受け入れ確認観点

JWTは将来HttpOnly Cookieで扱う。本番Cookie属性、固定7日、CSRF対策、既存Bearer方式からの移行は[共通認証フロー](../flows/authentication.md)に従う。

- パスワードやJWTをURL・ログ・永続ストレージへ残さない。
- アカウントの存在有無とパスワード不一致を、同じ認証失敗文言で通知する。
- 直接アクセス／「← 戻る」／新規登録リンクを確認する。
- 認証済みの入場時はフォームを表示せず、復帰先またはホームへ移動する。
- 保護画面からのログイン成功時は、元の目的画面へ戻る。
- 「← 戻る」後にウェルカムからログインした場合は、以前の目的画面へ戻らずホームへ進む。
- ログインから新規登録へ切り替えた場合、元の目的画面への復帰予定が引き継がれる。
- 認証確認失敗時は再試行できる。
- blur／送信時の検証、👁での表示切替、送信時の伏字復帰を確認する。
- 401でpasswordを消去し、通信失敗では両入力値を保持する。
- 二重送信防止、15秒タイムアウト、遅延応答の競合防止を確認する。
