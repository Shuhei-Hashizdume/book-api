# not-found.md — 404エラー画面仕様書

## 1. 画面概要

| 項目       | 内容                                                                            |
| ---------- | ------------------------------------------------------------------------------- |
| 画面名     | 404エラー画面                                                                   |
| ファイル名 | `not-found.md`                                                                  |
| 画面の目的 | 存在しないURLにアクセスしたユーザーにエラーを伝え、正常な画面へ戻れるようにする |
| 表示対象   | ログイン済み・未ログインの両ユーザー                                            |
| 表示条件   | アプリ内で定義されていないURLにアクセスした場合                                 |
| レイアウト | PC・スマホ共通の1カラム                                                         |
| 主な操作   | 「ホームに戻る」ボタン                                                          |

---

## 2. 画面の表示条件

### 2-1. 共通404画面を表示する場合

アプリ内で定義されていないURLにアクセスした場合、共通404画面を表示する。

例：

- 存在しないパスに直接アクセスした場合
- URLの入力を間違えた場合
- アプリ内に対応する画面が存在しないURLにアクセスした場合

### 2-2. 共通404画面を表示しない場合

URLに対応する画面自体は存在するものの、表示対象のデータが存在しない場合は、各画面のエラー表示を使用する。

| 状況                                           | 対応                           |
| ---------------------------------------------- | ------------------------------ |
| 存在しないユーザーのプロフィール               | `user-profile.md` のエラー表示 |
| 削除された読了投稿                             | `post-detail.md` のエラー表示  |
| その他、既存画面内で対象データが存在しない場合 | 各画面で定義されたエラー表示   |
| 定義されていないURL                            | 共通404画面                    |

共通404画面は、既存の画面ごとのエラー表示を置き換えない。

### 3-1. 基本レイアウト

通常のヘッダーメニューや下部ナビゲーションは表示しない。

## 4. 表示要素

| 要素         | 表示内容                                    | 仕様                           |
| ------------ | ------------------------------------------- | ------------------------------ |
| アプリロゴ   | BookAPP                                     | 画面上部に表示                 |
| アイコン     | 本のアイコン                                | 404メッセージの上に表示        |
| エラーコード | `404`                                       | 大きく表示                     |
| 見出し       | ページが見つかりません                      | エラー内容を明確に伝える       |
| 説明文       | URLが間違っているか、ページが存在しません。 | 原因を断定せず、簡潔に説明する |
| ボタン       | ホームに戻る                                | 画面内に1つだけ表示            |

### 4-1. アプリロゴ

- 画面上部にBookAPPロゴを表示する。
- ロゴは装飾として扱う。
- ロゴを押しても画面遷移しない。

### 4-2. エラーメッセージ

表示する文章は以下で固定する。

**エラーコード**

`404`

**見出し**

ページが見つかりません

**説明文**

URLが間違っているか、ページが存在しません。

### 4-3. ホームに戻るボタン

- ボタンの表示文言は「ホームに戻る」とする。
- 404画面内の主要操作ボタンとして表示する。
- ログイン状態に応じて遷移先を切り替える。
- 独自の「前の画面に戻る」ボタンは設けない。
- ブラウザ標準の戻る操作は通常どおり利用できる。

---

## 5. ボタン操作と画面遷移

### 5-1. 通常時の動作

「ホームに戻る」ボタンを押すと、ログイン状態を確認する。

| ログイン状態                       | 遷移先                      |
| ---------------------------------- | --------------------------- |
| ログイン済み                       | ホーム画面（`home.md`）     |
| 未ログイン                         | Welcome画面（`welcome.md`） |
| ログイン状態の確認に失敗           | Welcome画面（`welcome.md`） |
| ログインセッションが無効・期限切れ | Welcome画面（`welcome.md`） |

### 5-2. 遷移フロー

```text
┌───────────────────────────┐
│        404エラー画面      │
│                           │
│     [ ホームに戻る ]      │
└─────────────┬─────────────┘
              │
              ▼
      ログイン状態を確認
              │
       ┌──────┼───────────┐
       │      │           │
       ▼      ▼           ▼
  ログイン済み 未ログイン  確認失敗
       │      │           │
       ▼      ▼           ▼
    home.md welcome.md welcome.md
```

### 5-3. ログイン状態の確認中

- ボタン操作後、ログイン状態を確認する。
- 確認処理中はボタンの連打による重複遷移を防止する。
- 確認完了後、判定結果に応じた画面へ遷移する。

### 5-4. ログイン状態の確認に失敗した場合

- 404画面に留まらず、Welcome画面へ移動する。
- 404画面内に追加のエラーメッセージや再試行ボタンは表示しない。
- 認証確認の失敗だけを理由として、既存のログインセッションを明示的に削除しない。

## 6. URLの扱い

### 6-1. 元のURLを維持する

存在しないURLにアクセスした場合、ブラウザのアドレスバーに元のURLを残したまま共通404画面を表示する。

例：

```text
アクセスしたURL
https://example.com/unknown-page

          ↓

ブラウザのURL
https://example.com/unknown-page

表示される画面
404エラー画面
```

- 共通404画面を表示するために `/404` などの専用URLへリダイレクトしない。
- URLの入力ミスをユーザー自身が確認できる状態にする。
- 「ホームに戻る」ボタンを押した場合は、確定した遷移先のURLへ移動する。

※ `example.com` は説明用の仮ドメインであり、BookAPPの正式なURLではない。

### 6-2. HTTPステータス

- 未定義URLへの直接アクセスでは、可能な構成でHTTPステータス `404 Not Found` を返す。
- クライアント側の画面遷移と、サーバーへの直接アクセスの両方を考慮する。
- 実際のステータス応答はフロントエンドの配信方式に依存するため、画面表示とは別に確認する。

## 7. PC・スマホの表示仕様

### 7-1. 共通ルール

- PC・スマホともに1カラム構成とする。
- BookAPPロゴを画面上部に配置する。
- ロゴより下の表示領域の中央に404メッセージとボタンをまとめて配置する。
- 各要素は中央揃えを基本とする。
- 画面の横幅に応じて余白と文章の折り返しを調整する。

### 7-2. PC版

- 404メッセージの表示領域が横に広がりすぎないようにする。
- 画面中央にコンテンツをまとめる。
- 不必要なサイドバーやナビゲーションを設けない。

### 7-3. スマホ版

- 404メッセージが画面幅に収まるようにする。
- 説明文は必要に応じて改行する。
- ボタンはタップしやすいサイズを確保する。
- 画面が狭い場合は縦スクロールを許可する。
- 文字やボタンが画面外で切れないようにする。

## 8. ナビゲーション仕様

### 8-1. 表示するもの

- BookAPPロゴ
- 404エラーメッセージ
- 「ホームに戻る」ボタン

### 8-2. 表示しないもの

- 通常のヘッダーメニュー
- 下部ナビゲーション
- サイドバー
- 独自の「前の画面に戻る」ボタン
- その他の画面へ移動する追加ボタン

ログイン状態に関係なく、404画面の基本レイアウトは共通とする。

## 9. 画面状態

| 状態               | 表示・動作                                  |
| ------------------ | ------------------------------------------- |
| 初期表示           | 404メッセージと「ホームに戻る」ボタンを表示 |
| ボタン操作前       | 通常の404画面を表示                         |
| 認証状態の確認中   | 重複操作を防止                              |
| ログイン済みと判定 | ホーム画面へ遷移                            |
| 未ログインと判定   | Welcome画面へ遷移                           |
| 認証状態の確認失敗 | Welcome画面へ遷移                           |

404画面では、データ一覧の読み込みや検索、投稿操作などは行わない。

---

## 10. アクセシビリティ

- 404であることをアイコンだけに依存せず、見出しと説明文で伝える。
- 「ホームに戻る」ボタンはキーボードでも操作できるようにする。
- ボタンには視認できるフォーカス表示を設ける。
- テキストと背景のコントラストを確保する。
- スマホで文字サイズを拡大しても、文章やボタンが重ならないようにする。
- 本のアイコンは装飾として扱い、エラー内容はテキストで理解できるようにする。
