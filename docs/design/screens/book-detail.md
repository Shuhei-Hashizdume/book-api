# 登録済み書籍詳細画面 設計書

**ファイル名：** `docs/design/screens/book-detail.md`  
**対象画面：** 本棚に登録済みの書籍詳細画面  
**設計状態：** 主要UX仕様確定

---

## 1. 画面の目的

ユーザーが自分の本棚に登録した書籍の情報を確認し、読書状態・読む優先度・おすすめ度を変更できるようにする。

また、不要になった書籍を自分の本棚から削除できるようにする。

本画面は、書籍検索結果から本棚に追加するための `book-search-detail.md` とは別の画面として扱う。

## 2. PC版ワイヤーフレーム

```text
┌─────────────────────────────────────────────────────────┐
│ BookAPP                                   ユーザー ▼    │
├──────────────┬──────────────────────────────────────────┤
│ ホーム       │ ← 本棚に戻る                           │
│ 本棚         │                                          │
│ 気づき       │ ┌──────────┐  本のタイトル              │
│ タイムライン │ │          │  著者：著者名              │
│ マイページ   │ │   表紙   │  ジャンル：技術書          │
│              │ │          │                            │
│              │ └──────────┘                            │
│              │                                          │
│              │ 読書状態                                 │
│              │ ( ) 未読  (●) 読んでる  ( ) 読んだ       │
│              │                                          │
│              │ 読む優先度                               │
│              │ (●) 読みたい                             │
│              │ ( ) そのうち読みたい                     │
│              │                                          │
│              │           [ 変更を保存 ]                │
│              │                                          │
│              │ ───────────────────────────────────────  │
│              │ 本棚から削除                             │
└──────────────┴──────────────────────────────────────────┘
```

※ 初期表示では保存済みの値を選択状態にする。変更がなければ「変更を保存」は無効。

### 「読んだ」を選択した場合

```text
読書状態
( ) 未読  ( ) 読んでる  (●) 読んだ

おすすめ度（必須）
★ ★ ★ ☆ ☆

          [ 変更を保存 ]
```

この場合、読む優先度の入力欄は非表示にする。

## 4. 書籍情報の表示

| 項目     | 表示仕様                             | 編集 |
| -------- | ------------------------------------ | ---- |
| 表紙     | 書籍の表紙画像。なければ代替アイコン | 不可 |
| タイトル | 登録済み書籍のタイトル               | 不可 |
| 著者     | 登録済み書籍の著者                   | 不可 |
| ジャンル | 書籍に設定されたジャンル。複数可     | 不可 |

タイトル・著者・ジャンルは表示専用とし、本画面から編集できない。

登録日、あらすじ、ISBNは表示しない。

## 5. 読書状態の編集

選択肢は以下の3つ。

- 未読
- 読んでる
- 読んだ

画面を開いた際は、保存済みの読書状態を初期選択する。

読書状態に応じて表示する入力項目を切り替える。

| 選択中の読書状態 | 表示する項目 |
| ---------------- | ------------ |
| 未読             | 読む優先度   |
| 読んでる         | 読む優先度   |
| 読んだ           | おすすめ度   |

## 6. 読む優先度

選択肢は以下の2つ。

- 読みたい
- そのうち読みたい

「未読」「読んでる」の場合に表示する。

既存の優先度がある場合は保存済みの値を初期選択する。

「読んだ」に切り替えた場合は優先度の入力欄を非表示にするが、保存済みの優先度を削除しない。

再び「未読」「読んでる」に切り替えた場合は、以前の選択値を復元する。

## 7. おすすめ度

「読んだ」を選択した場合に表示する。

- ★1〜5から選択する。
- 「読んだ」の場合は必須。
- 保存済みのおすすめ度があれば初期選択する。
- 「未読」「読んでる」では非表示にする。

読書状態を切り替えても、保存済みのおすすめ度を削除しない。

画面内で別のおすすめ度を選んでから読書状態を切り替えた場合も、保存前の選択内容を保持する。

### データ保持の例

```text
保存済みデータ
  読書状態：読んでる
  優先度：読みたい
  おすすめ度：★4（過去の保存値）

        ↓

画面で「読んだ」に変更
  優先度：非表示
  おすすめ度：★4を表示

        ↓

画面で「未読」に変更
  優先度：読みたいを復元
  おすすめ度：非表示
```

※ 非表示の値を保存時にどのように扱うかは、バックエンドのデータモデルと整合させる必要がある。

## 8. 変更の保存

### 8.1 保存ボタンの有効条件

「変更を保存」ボタンは、保存済みデータと比較して実際に変更がある場合のみ有効にする。

以下の場合は無効にする。

- 何も変更していない。
- 一度変更した後、元の値に戻した。
- 「読んだ」を選択しているが、おすすめ度が未選択。

比較対象は読書状態・優先度・おすすめ度とし、保存対象となる値の変更を判定する。

### 8.2 保存成功

```text
登録済み書籍詳細
       │
       │「変更を保存」
       ▼
保存成功
       │
       ▼
本棚画面
       │
       ├─ 保存後が未読 → 未読タブ
       ├─ 保存後が読んでる → 読んでるタブ
       └─ 保存後が読んだ → 読んだタブ
```

本棚画面に以下のメッセージを数秒間表示する。

```text
✓ 変更を保存しました！
```

本棚一覧のスクロール位置は先頭に戻す。

### 8.3 保存失敗

- 書籍詳細画面に留まる。
- 編集中の入力内容を保持する。
- エラーメッセージを表示する。
- ユーザーが再度保存できるようにする。

例：

```text
変更を保存できませんでした。
もう一度お試しください。

[ 変更を保存 ]
```

### 8.4 保存処理中

二重送信を防止するため、保存処理中はボタンを無効化する。

表示例：

```text
[ 保存中... ]
```

これは登録画面と操作感を統一するための実装上の補足仕様。

## 9. 未保存の変更がある状態で戻る

画面上部の「← 本棚に戻る」を押した際、保存されていない変更が存在する場合は確認ダイアログを表示する。

```text
┌──────────────────────────────────┐
│ 変更内容が保存されていません。   │
│ 保存せずに戻りますか？           │
│                                  │
│ [編集を続ける] [保存せず戻る]    │
└──────────────────────────────────┘
```

### 編集を続ける

- ダイアログを閉じる。
- 入力内容を保持する。
- 書籍詳細画面に留まる。

### 保存せず戻る

- 編集内容を破棄する。
- 本棚画面へ戻る。
- 詳細画面を開く前に選択していたタブを表示する。
- スクロール位置は先頭に戻す。

実際の変更が存在しない場合は、確認ダイアログを表示せずに本棚へ戻る。

ブラウザの戻る操作や他の画面への移動でも、未保存変更を誤って破棄しないよう、画面遷移時の保護を検討する。

## 10. 本棚から削除

### 10.1 削除の対象

削除するのは、**現在ログインしているユーザーの本棚への登録情報**。

書籍マスターデータそのものや、他ユーザーの本棚から書籍を削除する操作ではない。

### 10.2 削除確認

「本棚から削除」を押した場合は、確認ダイアログを表示する。

```text
┌──────────────────────────────────┐
│ この本を本棚から削除しますか？   │
│                                  │
│ [キャンセル]     [削除する]      │
└──────────────────────────────────┘
```

### キャンセル

ダイアログを閉じ、書籍詳細画面に留まる。

### 削除する

削除APIを呼び出す。

処理中は二重操作を防ぐ。

### 10.3 削除成功

```text
登録済み書籍詳細
       │
       │「本棚から削除」
       ▼
削除確認
       │
       │「削除する」
       ▼
削除成功
       │
       ▼
本棚画面
  ・詳細画面を開く前のタブ
  ・スクロール位置は先頭
```

以下のメッセージを数秒間表示する。

```text
✓ 本棚から削除しました
```

### 10.4 削除失敗

- 詳細画面に留まる。
- エラーメッセージを表示する。
- 削除を再試行できるようにする。

## 11. 画面遷移の整理

| 操作           | 遷移先     | 本棚で選択するタブ |
| -------------- | ---------- | ------------------ |
| 変更なしで戻る | 本棚       | 元のタブ           |
| 保存せず戻る   | 本棚       | 元のタブ           |
| 保存成功       | 本棚       | 保存後の読書状態   |
| 削除成功       | 本棚       | 元のタブ           |
| 保存失敗       | 遷移しない | —                  |
| 削除失敗       | 遷移しない | —                  |

本棚へ戻る場合、スクロール位置は常に先頭とする。

## 12. 読み込み・エラー・例外

### 12.1 読み込み中

登録済み書籍データを取得するまでローディング表示を行う。

### 12.2 データ取得失敗

エラーメッセージと再試行ボタンを表示する。

### 12.3 書籍が存在しない場合

書籍が削除済み、または現在のユーザーの本棚に存在しない場合は、編集フォームを表示せず、本棚に戻れる案内を表示する。

### 12.4 権限

他ユーザーの本棚登録情報を編集・削除できないよう、バックエンドで認可を行う。

## 13. API・バックエンドとの関係

### 13.1 登録済み書籍の取得

既存の想定エンドポイント：

```http
GET /users/me/books/{book_id}
```

画面表示に必要な書籍情報・読書状態・優先度・おすすめ度を取得する。

実際のレスポンスにすべて含まれているかは実装時に確認する。

### 13.2 読書状態の更新

既存の想定エンドポイント：

```http
PATCH /users/me/books/{book_id}/status
```

既存バックエンドでは読書状態の更新と、読了時のおすすめ度設定に関係する処理が存在する。

本画面で必要な更新対象：

- 読書状態
- 読む優先度
- おすすめ度

**既存のステータス更新APIだけですべての値を更新できるとは限らない。**

優先度の更新方法や複数項目の保存順序、途中失敗時の整合性は実装時に確認する。

### 13.3 本棚からの削除

現在のユーザーの本棚登録情報を削除する既存APIを確認して利用する。

エンドポイント名は未検証のため、本書では確定しない。

### 13.4 データモデルの整合性

優先度は旧3段階から新2段階に変更する。

また、読書状態を切り替えても優先度・おすすめ度の保存済み値を保持する必要がある。

既存の `UserBook`、評価関連モデル、読了関連モデルとの整合性を確認し、必要に応じてAPI・DBを改修する。

## 14. 本画面で扱わないこと

- 書籍タイトル・著者・ジャンルの編集
- 書籍検索
- 新規書籍登録
- 気づきの登録・編集
- AI提案
- 書籍マスターデータの削除

これらは必要に応じて別の画面設計書で扱う。

## 15. 確定事項

- 登録済み書籍詳細画面は検索結果詳細画面と分ける。
- タイトル・著者・ジャンルは表示のみで編集できない。
- 登録日・あらすじ・ISBNは表示しない。
- 読書状態は「未読」「読んでる」「読んだ」の3種類。
- 優先度は「読みたい」「そのうち読みたい」の2種類。
- 「読んだ」ではおすすめ度★1〜5を必須とする。
- 読書状態の切り替えで保存済みの優先度・おすすめ度を消去しない。
- 保存済みの値から変更がない場合、保存ボタンは無効。
- 保存成功時は保存後の読書状態に対応する本棚タブへ遷移。
- 未保存の変更がある場合、戻る前に確認する。
- 削除前に確認ダイアログを表示する。
- 削除するのは現在のユーザーの本棚登録情報。
- 保存・削除失敗時は詳細画面に留まる。
- 本棚へ戻った際のスクロール位置は先頭。

## 16. 実装時の確認事項

- 詳細取得APIのレスポンス項目。
- 優先度を更新するAPIの有無。
- 読書状態・優先度・おすすめ度を一括保存するかどうか。
- 読書状態の切り替え後も過去の評価を保持できるDB構造。
- 旧優先度データの移行方法。
- 本棚から削除する既存APIの仕様。
- 未保存変更がある場合のブラウザ戻る・別画面遷移の制御方法。
- 共通ナビゲーションのスマホ表示仕様。
