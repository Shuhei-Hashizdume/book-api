# 気づき新規登録画面 設計書

- ファイル名：`docs/design/screens/insight-create.md`
- 画面：気づき新規登録
- 状態：最大文字数2,000文字を反映した修正版
- 遷移元：書籍別の気づき一覧（`book-insights.md`）
- 保存後：同じ書籍の気づき一覧に戻る

## 1. 目的

選択中の書籍について、ユーザーが読書から得た気づきを文章で保存する。タイトル・画像・タグ・添付ファイルは設けず、本文のみを入力する。

## 2. 確定仕様

| 項目 | 仕様 |
|---|---|
| 対象書籍 | 遷移元で選択された書籍。画面内で変更不可 |
| 入力項目 | 気づき本文のみ |
| 必須 | 必須。空文字・空白だけの入力は不可 |
| 最大文字数 | **2,000文字** |
| 改行 | 入力可能 |
| 文字数表示 | 現在の文字数 / 2,000文字 |
| 保存成功 | 同じ書籍の気づき一覧へ戻り、新しい気づきを先頭に表示 |
| AI提案 | 保存時には自動生成しない |
| 保存中 | ローディング表示・二重送信防止 |
| 保存失敗 | 入力を保持し、エラーを表示 |
| 未保存で離脱 | 入力がある場合は確認ダイアログを表示 |

## 5. 入力とバリデーション

- 本文は1文字以上、2,000文字以下とする。
- 前後の空白を除去した結果が空の場合は保存できない。
- 改行を含む複数行の文章を保存できる。
- 文字数カウンターは入力に応じて更新する。
- 2,000文字を超える内容は保存できない。超過時はエラーを表示し、入力内容は保持する。
- フロントエンドとバックエンドの双方で検証する。画面の制限だけに依存しない。
- 文字数の数え方はフロントエンドとバックエンドで一致させる。絵文字等のUnicode文字を含む入力で差異が生じないようテストする。

### エラー表示例

```text
気づき本文 *
┌──────────────────────────────┐
│ （入力内容）                 │
└──────────────────────────────┘
2,015 / 2,000文字
気づき本文は2,000文字以内で入力してください。

[気づきを保存]  ← 保存不可
```

## 7. バックエンド対応

既存の登録API：

```http
POST /users/me/books/{book_id}/insights
```

Pydanticの作成スキーマに最大文字数を追加する。既存の`min_length=1`に加え、`max_length=2000`を指定する。

```python
class InsightCreate(BaseModel):
    model_config = ConfigDict(str_strip_whitespace=True)
    content: str = Field(min_length=1, max_length=2000)
```

※ 上記は実装方針の例であり、コード変更が完了したことを意味しない。所有権・認証の検証は既存APIの責務として維持する。

## 8. 実装時に確認する事項

- 気づき一覧の新着順表示には作成日時が必要。現行モデルの`created_at`未実装に対応する。
- 保存直後の一覧表示は、新しい気づきが先頭に表示されるようにする。
- フロントエンドの文字数判定とPydanticの判定を一致させる。
- 既存データに2,000文字を超える気づきが存在する場合の扱いを、データを失わない方法で検討する。
