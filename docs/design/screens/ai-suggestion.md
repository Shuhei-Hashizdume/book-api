# AI提案画面 設計書（改訂版）

- ファイル名：`docs/design/screens/ai-suggestion.md`
- 対象画面：AI提案
- 前画面：`insight-detail.md`（気づき詳細）
- 対象ユーザー：ログイン済みユーザー
- 改訂内容：**AI生成と保存が両方成功した場合のみ、1日5回の利用枠を1回消費する（A案確定）**

## 1. 目的

ユーザーが本から得た気づきをAIで整理・深掘りし、実生活での活用と数日以内に実行できる具体的行動につなげる。生成時には書籍タイトル、著者名、気づき本文、ユーザー属性を参考にする。属性から生活状況を断定しない。

## 2. AI提案の4項目

| 表示名 | APIレスポンス項目 | 内容 |
|---|---|---|
| ① 気づきの整理 | `clarified_insight` | 元の意味を尊重して整理する |
| ② 気づきの深掘り | `deep_dive` | 背景や重要性を掘り下げる |
| ③ 実生活での活用方法 | `practical_application` | ユーザー属性も参考に活用場面を提案する |
| ④ 次に取る具体的な行動 | `next_action` | 今日から数日以内にできる行動を1つ示す |

4項目は省略せず全文表示する。

## 5. 新規生成の動作

1. 気づき詳細画面で、AI提案がない場合に「AI提案を生成」を表示する。
2. ボタン操作後、バックエンドでユーザー認証、気づきへのアクセス権、当日利用枠を確認する。
3. 利用枠があればAI生成を開始する。生成中はローディングを表示し、二重送信を防ぐ。
4. **4項目の生成とDBへの保存が両方成功したときに限り、利用回数を1回加算する。**
5. 保存成功後、AI提案画面を表示し、残り回数を更新する。
6. AI生成失敗・保存失敗の場合はエラーを表示し、**利用回数は消費しない**。

## 6. 再生成の動作

- 保存済みAI提案がある場合に「AI提案を再生成」を表示する。
- 再生成前に確認ダイアログを表示する。

```text
┌──────────────────────────────────┐
│ AI提案を再生成しますか？         │
│                                  │
│ 現在の提案は新しい提案に         │
│ 置き換わります。                 │
│                                  │
│ [ キャンセル ] [ 再生成する ]    │
└──────────────────────────────────┘
```

- キャンセル：何も変更せず、回数も消費しない。
- 再生成開始：ボタン無効化、ローディング表示、二重送信防止。
- **再生成とDB更新が成功した場合のみ1回消費**し、新しい4項目を表示する。
- AI生成またはDB更新が失敗した場合：**回数は消費せず、以前のAI提案を保持**する。
- 上限到達時：再生成を受け付けない。保存済み提案の閲覧は可能。

## 7. 1日5回の利用制限【確定】

| 項目 | 確定仕様 |
|---|---|
| 上限 | **1ユーザーにつき1日5回** |
| カウント対象 | **新規生成＋再生成の合計** |
| カウント確定タイミング | **AI生成とDB保存・更新がともに成功したとき** |
| AI生成失敗 | **0回消費** |
| DB保存・更新失敗 | **0回消費** |
| 確認ダイアログのキャンセル | **0回消費** |
| 保存済み提案の閲覧（GET） | **0回消費** |
| リセット | **日本時間（Asia/Tokyo）の毎日0:00** |
| 上限超過 | **新規生成・再生成を拒否（HTTP 429）** |
| 判定場所 | **バックエンド。画面表示だけの制御は不可** |

### 利用例

```text
当日開始：0 / 5回 使用（残り5回）
  ├─ 気づきAの新規生成＋保存成功 → 1 / 5回（残り4回）
  ├─ 気づきAの再生成でAIエラー → 1 / 5回（残り4回のまま）
  ├─ 気づきAの再生成＋保存成功 → 2 / 5回（残り3回）
  ├─ 気づきBの新規生成で保存失敗 → 2 / 5回（残り3回のまま）
  ├─ 別の成功した生成3件 → 5 / 5回（残り0回）
  └─ さらに生成を試みる → HTTP 429、生成処理を開始しない
翌日0:00 JST → 新しい日の残り5回
```

### 上限到達時の表示

```text
本日の残り生成回数：0 / 5回
本日のAI提案の利用上限に達しました。
明日またご利用ください。
[ 🔄 AI提案を再生成 ]（無効）
```

新規生成ボタンにも同様の無効状態・メッセージを適用する。閲覧は妨げない。

### サーバー側の必須要件

- ユーザーIDとJST利用日で回数を管理する。クライアント時刻を信用しない。
- **同時リクエストで5回を超えない**よう、利用枠の予約・排他制御などを行う。生成中リクエストも含めて上限を守る。
- 予約枠を用いる場合、生成失敗・保存失敗では枠を解放し、**成功回数に算入しない**。
- **提案の保存成功と回数加算の整合性を保証**する。DBトランザクションなどで「保存は成功したが回数だけ加算されない」「回数は加算されたが保存されない」を防ぐ。
- 二重送信・通信再試行による意図しない二重課金・二重カウントを防ぐため、リクエストの重複対策を実装する。
- 生成失敗を無料扱いにしてもAPI費用が発生する可能性があるため、短時間の連続試行・同時実行・障害時の再試行には別途制御を設ける。
- 残り回数はサーバーの情報を取得して表示し、成功後・日付変更後に更新する。

※ 利用枠の予約方法、重複対策、DB構造は実装時に具体化する。**上記の動作要件は確定**。

## 8. 気づき編集・ユーザー属性変更

- 気づき編集後も既存AI提案を削除しない。
- 生成時の気づき内容と現在の内容が異なる場合、再生成を推奨する表示を設ける（比較情報の保持方法は実装検討）。
- ユーザー属性を変更しても既存AI提案は削除しない。
- 次回生成時は最新のユーザー属性を使う。
- 気づきや属性の変更だけでは自動生成しない。再生成はユーザー操作のみ。
- 新規生成・再生成ともに、入力として使う気づき本文の上限は**2,000文字**（別途確定した共通仕様）。

```text
[気づき詳細]
   ├─ AI提案なし → [AI提案を生成]
   │                   ├─ 残りあり → [生成中] ─ 成功＋保存成功 → [AI提案画面]
   │                   │                    └─ 失敗 → エラー表示／回数維持
   │                   └─ 残り0回 → 上限メッセージ
   │
   └─ AI提案あり → [AI提案を見る] → [AI提案画面]
                                          ├─ [再生成] → [確認]
                                          │                 ├─ キャンセル → 現状維持
                                          │                 └─ 実行 → 成功＋更新成功 → 新提案／1回消費
                                          │                           └─ 失敗 → 旧提案維持／0回消費
                                          └─ [戻る] → [気づき詳細]
```

## 10. API・バックエンドとの対応

既存のAPI（GitHub上の`routers/ai_suggestions.py`で確認した範囲）：

```http
POST   /users/me/books/{book_id}/insights/{insight_id}/ai-suggestion
GET    /users/me/books/{book_id}/insights/{insight_id}/ai-suggestion
DELETE /users/me/books/{book_id}/insights/{insight_id}/ai-suggestion
```

- POSTは新規生成でHTTP 201、再生成でHTTP 200を返す。
- GETは保存済み提案の閲覧。回数を消費しない。
- DELETEは既存APIとして存在するが、本画面に削除ボタンを設置するかは本仕様では決定していない。
- **日次5回制限、HTTP 429、残り回数の取得、失敗時非消費は追加実装が必要**。現行実装済みとは扱わない。
- AI生成にユーザー属性を渡す処理も追加実装が必要。
- 利用枠の取得APIのURL、DBテーブル構成、競合制御方式はバックエンド設計時に決定する。

## 11. エラー表示とデータ保護

| 状況 | 動作 | 利用回数 |
|---|---|---|
| AI生成成功＋保存成功 | 提案表示・残回数更新 | 1回消費 |
| AI生成失敗 | エラー表示・再試行案内 | 消費しない |
| DB保存・更新失敗 | エラー表示・再試行案内。旧提案を保持 | 消費しない |
| 上限超過 | HTTP 429、生成停止 | 消費しない |
| 認証切れ | 再ログイン案内 | 消費しない |
| 他人の気づき・存在しない気づき | 権限・存在確認エラー | 消費しない |
| 確認ダイアログでキャンセル | 元の画面に戻る | 消費しない |

通信断などで「サーバー側では成功したが画面に結果が届かなかった」場合は、再送前に保存済み提案と利用状況を再取得できるようにする。単純な再送で意図せず2回消費しない仕組みが必要。

## 12. 確定事項と実装検討事項

### 確定事項

- AI提案は4項目で全文表示する。
- 新規生成と再生成は手動操作のみ。
- 再生成前に確認し、成功した場合に既存提案を置き換える。
- 再生成失敗時は既存提案を保持する。
- 1ユーザー1日5回、JST0:00でリセット。
- 新規生成と再生成を合算する。
- **生成・保存の両方が成功した場合のみ1回消費。AI生成失敗・保存失敗は0回。**
- 上限到達時は生成を止めるが、保存済み提案の閲覧は可能。
- バックエンドで回数制限を保証する。
- 気づき本文の上限は2,000文字。

### 実装時に具体化する事項

- 利用回数のDB構造と予約・解放の方法
- 保存と回数加算のトランザクション設計
- 並行リクエストと重複リクエスト対策
- 残り回数取得APIと画面更新タイミング
- 気づき編集後の提案の鮮度判定
- API費用監視・障害時の試行制御
