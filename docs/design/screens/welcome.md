# BookAPP ウェルカム画面設計

作成日：2026-10-19  
更新日：2026-10-20  
状態：画面の基本仕様・表示内容・操作・画面遷移は確定。認証基盤の一部詳細と共通デザインは未決定。

## 1. 画面の目的

ウェルカム画面は、BookAPPにアクセスした未ログインの利用者が、最初に利用方法を選択するための画面である。

利用者は以下の3つから操作を選択できる。

1. 新規登録する
2. ログインする
3. 登録せずにBookAPPを閲覧する

ログイン済みの利用者はウェルカム画面に留まらず、ログイン済みホーム画面へ自動的に遷移する。

### 1.1 対象となる利用者

| 利用者の状態                 | 動作                     |
| ---------------------------- | ------------------------ |
| 未ログイン                   | ウェルカム画面を表示     |
| ログイン済み                 | ホーム画面へ自動遷移     |
| 認証確認中                   | 共通ローディングを表示   |
| 認証確認に失敗               | エラーと再試行操作を表示 |
| ログイン期限切れと識別できた | ログイン画面へ遷移       |

認証確認の詳細は[共通認証フロー](../flows/authentication.md)に従う。

## 2. 画面の表示内容

画面中央に以下の要素を上から順に表示する。

| 順序 | 要素             | 表示内容                               |
| ---- | ---------------- | -------------------------------------- |
| 1    | アプリ名         | BookAPP                                |
| 2    | キャッチコピー   | 読書の記録から、新しい本との出会いへ。 |
| 3    | 新規登録ボタン   | 新規登録する                           |
| 4    | ログインボタン   | ログインする                           |
| 5    | ゲスト閲覧ボタン | BookAPPを覗いてみる                    |

### 2.1 配置ルール

- アプリ名、キャッチコピー、3つのボタンをひとまとまりとして配置する。
- PC・スマートフォンともに、画面の横方向・縦方向の中央配置を基本とする。
- 3つのボタンは縦方向に配置する。
- PCでもボタンを横並びにしない。
- ボタンの表示順は変更しない。
- キャッチコピーは画面幅に応じて自然に改行する。
- ヘッダーは設けない。
- フッターは現時点では設けない。
- ボタンの具体的な色・形状・文字サイズなどは共通デザインで定義する。

## 5. ボタンの操作仕様

### 5.1 新規登録する

**表示文言：** `新規登録する`

押下すると新規登録画面へ遷移する。

- 遷移先：`signup.md` に定義する新規登録画面
- ウェルカム画面上では登録APIを呼び出さない。
- 利用者情報の入力は新規登録画面で行う。

### 5.2 ログインする

**表示文言：** `ログインする`

押下するとログイン画面へ遷移する。

- 遷移先：`login.md` に定義するログイン画面
- ウェルカム画面上ではログインAPIを呼び出さない。
- メールアドレスとパスワードの入力はログイン画面で行う。

### 5.3 BookAPPを覗いてみる

**表示文言：** `BookAPPを覗いてみる`

押下すると、未ログイン状態のままホーム画面へ遷移する。

- アカウント登録を要求しない。
- ログインを要求しない。
- 公開情報を閲覧できる。
- ログイン必須の機能を使用する場合は、共通のログイン案内を表示する。

ゲスト用に独立した別画面を用意するのではなく、ホーム画面の認証状態に応じて表示内容を切り替える。

具体的なゲスト表示は[ホーム画面設計](home.md)に従う。

## 6. 画面遷移

### 6.1 基本フロー

```text
                 BookAPPへアクセス
                         |
                         v
                   認証状態を確認
                         |
             +-----------+-----------+
             |                       |
             v                       v
         未ログイン               ログイン済み
             |                       |
             v                       v
       ウェルカム画面          ログイン済みホーム
             |
     +-------+--------+----------------+
     |                |                |
     v                v                v
 新規登録する      ログインする    BookAPPを覗いてみる
     |                |                |
     v                v                v
 新規登録画面      ログイン画面       ゲスト用ホーム表示
```

### 6.2 ログイン・新規登録成功後

ウェルカム画面から直接ログイン・新規登録を開始し、認証に成功した場合は、ログイン済みホーム画面へ遷移する。

一方、ゲストがログイン必須の画面へアクセスしようとして認証画面へ移動した場合は、認証成功後に元々アクセスしようとしていた画面へ遷移する。

```text
【ウェルカムからログイン】

ウェルカム
    |
    v
ログイン画面
    |
    v
ログイン成功
    |
    v
ホーム画面


【ログイン必須の画面からログイン】

ゲスト用ホーム
    |
    v
本棚を選択
    |
    v
ログインが必要です
    |
    v
ログイン画面
    |
    v
ログイン成功
    |
    v
本棚画面
```

ログイン後の復帰先を保持する具体的な仕組みは共通認証フローで管理する。

## 7. 認証状態別の表示仕様

### 7.1 認証確認中

認証状態が確定するまで、ウェルカム画面の3つのボタンは表示しない。

共通ローディングを表示する。

```text
+----------------------------------+
|                                  |
|                                  |
|             BookAPP              |
|                                  |
|           読み込み中...          |
|                                  |
|                                  |
+----------------------------------+
```

PC・スマートフォンともに同じメッセージを表示する。

### 7.2 ログイン済み

`GET /users/me` によってログイン済みと確認できた場合、ウェルカム画面を表示せずにログイン済みホーム画面へ遷移する。

認証情報が保存されているという理由だけでログイン済みとは判断しない。

### 7.3 初回未ログイン

有効な認証情報がなく、未ログインと判断できた場合は通常のウェルカム画面を表示する。

### 7.4 ログイン期限切れ

ログイン期限切れと識別できた場合は、ログイン画面へ遷移し、以下を表示する。

`ログインの有効期限が切れました。もう一度ログインしてください。`

ただし、既存バックエンドの401レスポンスでは期限切れとその他の認証エラーを区別できない。

期限切れの識別方法は共通認証フローで定義する。

### 7.5 不正または理由不明の401

期限切れと識別できない401レスポンスは、期限切れと断定しない。

未認証としてウェルカム画面を表示する。

無効な認証情報の削除方法などは共通認証フローで管理する。

### 7.6 通信障害・タイムアウト・サーバーエラー

認証状態を確認できない場合、未ログインと決めつけず、エラー画面を表示する。

表示文言：

`ログイン状態を確認できませんでした。`

操作：

`再試行する`

再試行すると認証状態の確認を再実行する。

#### PC版

```text
+--------------------------------------------------------------------+
|                                                                    |
|                                                                    |
|                              BookAPP                               |
|                                                                    |
|              ログイン状態を確認できませんでした。                    |
|                                                                    |
|                         [ 再試行する ]                             |
|                                                                    |
|                                                                    |
+--------------------------------------------------------------------+
```

#### スマートフォン版

```text
+----------------------------------+
|                                  |
|             BookAPP              |
|                                  |
|    ログイン状態を                 |
|    確認できませんでした。         |
|                                  |
|         [ 再試行する ]           |
|                                  |
+----------------------------------+
```

この状態では新規登録・ログイン・ゲスト閲覧の3つのボタンを表示しない。

## 8. 既存バックエンドとの対応

以下は2026-10-19時点の既存コード調査に基づく。

| 項目                | 既存バックエンド                                             | ウェルカム画面との関係 |
| ------------------- | ------------------------------------------------------------ | ---------------------- |
| `POST /users/login` | メールアドレス・パスワードを受け取り、アクセストークンを返す | ログイン画面で利用     |
| `GET /users/me`     | 認証された利用者の情報を返す                                 | 認証状態の確認に利用   |
| JWT Bearer認証      | `Authorization: Bearer <access_token>` で認証                | 現在の認証方式         |
| 無効・期限切れJWT   | 認証失敗として401を返す                                      | 現状は原因の識別が困難 |

### 8.1 認証方式の将来仕様

認証方式は将来的にJWTをHttpOnly Cookieで管理する方針である。

共通認証フローで定義されている方針：

- ログインから固定7日間の有効期限
- スライディング延長なし
- 本番Cookie属性：`HttpOnly=True`、`Secure=True`、`SameSite=Lax`
- CSRF対策としてOrigin検証とSameSite=Laxを併用

Cookie名、適用範囲、開発環境での属性、期限切れ識別方法などの詳細は[共通認証フロー](../flows/authentication.md)で管理する。

ウェルカム画面は認証方式の内部実装に依存せず、認証確認結果に応じて表示・遷移を切り替える。
