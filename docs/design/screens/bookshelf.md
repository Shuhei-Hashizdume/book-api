# BookAPP — 本棚画面設計書

- **リポジトリ内保存先:** `docs/design/screens/bookshelf.md`
- **対象画面:** 本棚一覧（PC・スマートフォン）
- **仕様基準日:** 2026-10-20
- **状態:** UX・画面仕様確定版。API／DBの実装差分は別途確認する。
- **設計原則:** 1画面につき1Markdown。本書は本棚一覧画面のみを扱い、検索画面・検索結果詳細画面・登録済み書籍詳細画面の内部仕様はそれぞれ別の設計書に記載する。

## 1. 画面の目的

ユーザー自身が登録した本を、**未読・読んでる・読んだ**の状態別に見つけ、書籍詳細画面へ進めるようにする。本棚は読書の学びを実生活の行動につなげるBookAPPの入口の一つであり、過度な管理機能を増やさず「本を探す」「本を見る」に集中する。

## 2. 確定仕様の一覧

| 項目 | 仕様 |
|---|---|
| 画面タイトル | 本棚 |
| タブ | 左から **未読／読んでる／読んだ**。**すべて**タブは設けない |
| 通常の初期表示 | 未読タブ |
| 一覧形式 | 書籍を縦方向に表示し、スクロール可能。ページネーション等の追加UIは現段階では設けない |
| 1冊の表示情報 | 表紙画像、タイトル、著者、優先度またはおすすめ度、詳細への遷移表示 |
| 未読・読んでるの補足情報 | 優先度を **読みたい／そのうち読みたい** の文言でそのまま表示 |
| 読んだの補足情報 | おすすめ度（★1〜5）を表示。優先度は表示しない |
| 優先度の並び | 未読・読んでるは **読みたい → そのうち読みたい**。同一優先度では**本棚への登録が新しい順** |
| 読んだの並び | 本棚への登録が新しい順 |
| 一覧の操作 | 書籍行のタップ／クリックで**登録済み書籍詳細画面**へ遷移。一覧で直接編集しない |
| 検索への入口 | 画面上部の **＋ 本を探す**。空状態では中央にも **本を探す** |
| 本棚に戻った際のスクロール | **すべて先頭**。以前の「位置を保持」は取り消し |
| 空状態 | タブ別の案内文と「本を探す」ボタン |
| 読み込み中 | ローディング表示 |
| 通信エラー | エラーメッセージと再試行ボタン |
| 表紙画像なし | 書籍アイコン等の代替表示 |

### 2.1 読書状態とタブの対応

| タブ表示 | 内部状態（現行APIの想定） | 補足情報 |
|---|---|---|
| 未読 | `want_to_read` | 優先度 |
| 読んでる | `reading` | 優先度 |
| 読んだ | `completed` | おすすめ度 |

**注意:** 優先度は旧仕様の「高・中・低」から、**「読みたい／そのうち読みたい」の2択**へ変更済み。新規登録時の初期選択は「読みたい」。旧3段階のまま画面に表示しない。バックエンド上の保存値と既存データ移行は実装時に調整する。

│               │        岸見一郎・古賀史健                │
│               │        読みたい                          │
│               │ ──────────────────────────────────────── │
│               │ [表紙] 書籍B                          > │
│               │        著者B                             │
│               │        読みたい                          │
│               │ ──────────────────────────────────────── │

- PC版は共通ヘッダー＋左サイドバーを使用し、本棚を現在地として表示する。
- タブ・一覧・検索ボタンは本棚のメイン領域に配置する。
- 表示例は**未読タブ**。読んでるも優先度順、読んだはおすすめ度表示・登録新着順。

- 共通ヘッダーと下部ナビゲーションを使用する。
- 下部ナビゲーションの「本棚」を選択状態とする。
- 横幅に応じてタイトル・著者を折り返しまたは適切に省略し、タブや操作が画面外にはみ出ないようにする。具体的な余白・色・タイポグラフィは共通デザイン定義に従う。

## 5. タブ切り替えと並び順

1. 本棚を通常のメニューから開くと「未読」を選択する。
2. タブを押すと、その読書状態に該当する**自分の本**だけを表示する。
3. **未読・読んでる:** 「読みたい」を先、「そのうち読みたい」を後に並べる。同じ優先度内では本棚への登録日時が新しい順。
4. **読んだ:** 本棚への登録日時が新しい順。おすすめ度の高い順には並べない。
5. 並び替え基準は**ユーザーがその本を本棚へ登録した日時**であり、書籍マスタの作成日時とは区別する。
6. 本棚に戻ったときは、どの経路でも一覧の**先頭**を表示する。スクロール位置の復元は行わない。

## 6. 操作・画面遷移

```text
[ホーム／共通ナビ]
         │ 本棚を開く
         ▼
[本棚：未読タブ／先頭]
    ├─ タブ選択 ────────────────→ [本棚：選択したタブ]
    ├─ ＋ 本を探す ─────────────→ [書籍検索画面]
    └─ 書籍行を選択 ────────────→ [登録済み書籍詳細画面]
                                        │
                                        ├─ 通常戻る／変更破棄 → 元のタブ・先頭
                                        ├─ 編集保存成功     → 保存後の状態のタブ・先頭
                                        └─ 削除成功         → 元のタブ・先頭

[書籍検索 → 検索結果詳細 → 本棚への新規登録成功]
         └──────────────────────→ [本棚：登録した状態のタブ・先頭]
```

| 遷移のきっかけ | 遷移先タブ | スクロール |
|---|---|---|
| メニューから本棚を開く | 未読 | 先頭 |
| 書籍詳細から通常戻る | 詳細を開く直前のタブ | 先頭 |
| 未保存の変更を破棄して戻る | 詳細を開く直前のタブ | 先頭 |
| 書籍の新規登録成功 | 登録した読書状態のタブ | 先頭 |
| 書籍の編集保存成功 | 保存後の読書状態のタブ | 先頭 |
| 本棚から削除成功 | 詳細を開く直前のタブ | 先頭 |

- 新規登録成功時は「✓ 本棚に追加しました！」を数秒表示する。
- 編集保存成功時は「✓ 変更を保存しました！」を数秒表示する。
- 削除成功時は「✓ 本棚から削除しました」を数秒表示する。
- 編集・削除の操作そのもの、未保存変更の確認ダイアログ、優先度／おすすめ度の編集は**登録済み書籍詳細画面**の責務であり、本棚一覧に入力フォームを追加しない。

## 7. 画面の状態と例外

### 7.1 空状態（タブごと）

```text
┌─────────────────────────────────┐
│ 📚 本棚           ＋ 本を探す   │
│                                 │
│ [未読] [● 読んでる] [読んだ]   │
│                                 │
│              📖                 │
│                                 │
│   読んでいる本はまだありません  │
│   気になる本を探してみましょう  │
│                                 │
│          [本を探す]            │
└─────────────────────────────────┘
```

| タブ | 見出し |
|---|---|
| 未読 | 未読の本はまだありません |
| 読んでる | 読んでいる本はまだありません |
| 読んだ | 読み終えた本はまだありません |

補助文は「気になる本を探してみましょう」。中央の「本を探す」も上部の「＋ 本を探す」と同じ検索画面へ遷移する。削除後に0冊になった場合も同じ表示。

### 7.2 読み込み中

- 対象タブの一覧取得中はローディング表示を出す。
- 取得前に0冊と断定する空状態を表示しない。

### 7.3 通信エラー

- 「本の一覧を読み込めませんでした」等の案内と「再試行」を表示する。
- 再試行は現在選択中のタブのデータ取得を再実行する。

### 7.4 表紙画像がない場合

- 表紙の位置には書籍アイコン等の代替表示を置く。行のレイアウトは維持する。

### 7.5 長い文字列

- 長いタイトル・著者名でも他の情報や操作を覆わないこと。詳細な省略行数は共通UI実装で調整する。

## 8. 他画面との責務の境界

| 別画面 | 本棚からの関係 | 本書に含めない仕様 |
|---|---|---|
| 書籍検索画面 | 「本を探す」から遷移 | 検索入力、結果表示、検索エラー、検索結果保持 |
| 検索結果の書籍詳細画面 | 検索結果から遷移し、本棚登録を実行 | 登録フォーム、重複登録判定、登録失敗時の入力保持 |
| 登録済み書籍詳細画面 | 本棚の書籍行から遷移 | 読書状態／優先度／おすすめ度の編集、保存ボタン、削除確認、未保存変更の警告 |
| 気づき画面 | 将来の中心機能 | 気づきの入力・AI提案・実践・振り返りの具体的UI |

検索・登録済み書籍詳細に関する決定済み事項は、それぞれの画面Markdownに記録する。本棚一覧の設計書へフォーム仕様を重複記載しない。

## 9. API／データモデルとの整合性（実装時の確認事項）

以下は**画面仕様の未決定ではなく、既存実装との差分・要検証事項**。

1. **一覧取得:** 既存の `GET /users/me/books` は `list_type` による区分を前提としているため、`未読／読んでる／読んだ` の3タブを適切に取得・絞り込めるか確認する。必要ならAPIのフィルタ仕様を変更する。
2. **優先度の2択化:** 現行の `high / medium / low` を、UIの「読みたい／そのうち読みたい」に整合する保存値へ変更する。既存の `medium` データの移行方針を定める。新規登録時の初期値は「読みたい」。
3. **登録日時:** 本棚登録単位の日時で並べられるか確認する。書籍マスタ作成日時で代用しない。
4. **優先度順:** 未読・読んでるは優先度を第1キー、登録日時を第2キーとして安定した順序を返す。サーバー／クライアントのどちらでソートするかは実装時に決める。
5. **読了おすすめ度:** `completed` の書籍について、一覧表示に必要な1〜5のおすすめ度を取得できるか確認する。
6. **遷移状態:** 登録・保存・削除の結果に応じたタブ選択と成功メッセージを画面間で受け渡せるようにする。通常アクセス時は未読を初期表示。
7. **本人データ:** 一覧には認証済みユーザー自身の登録書籍のみを表示する。

- [ ] 一覧の各行に表紙・タイトル・著者・適切な優先度またはおすすめ度が表示される。
- [ ] 未読・読んでるは「読みたい」が先、同一優先度は登録新着順。読んだは登録新着順。
- [ ] 書籍行から登録済み書籍詳細へ、検索ボタンから書籍検索へ移動できる。
- [ ] 本棚へ戻る全経路でスクロールが先頭になる。遷移ごとのタブ選択が表どおり。
