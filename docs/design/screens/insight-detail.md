# 気づき詳細画面 設計書

- ファイル名：`docs/design/screens/insight-detail.md`
- 画面：気づき詳細・インライン編集
- 状態：編集時の最大文字数2,000文字を反映した修正版
- 遷移元：書籍別の気づき一覧（`book-insights.md`）

## 1. 目的

登録済みの気づきを全文表示し、その場で編集・削除できるようにする。また、選択中の気づきに対するAI提案の生成・閲覧へ進める。

## 2. 確定仕様

| 項目 | 仕様 |
|---|---|
| 気づき表示 | 本文全文、書籍情報、登録日 |
| 編集方法 | **詳細画面内のインライン編集**（別画面へ移動しない） |
| 編集対象 | 気づき本文のみ |
| 編集時の必須条件 | 空文字・空白のみ不可 |
| 編集時の最大文字数 | **2,000文字** |
| 文字数表示 | 編集時に現在の文字数 / 2,000文字を表示 |
| 保存成功 | 詳細表示に戻り、更新後の本文を表示 |
| 保存失敗 | 編集中の本文を保持してエラー表示 |
| 削除 | 確認後に削除し、書籍別の気づき一覧へ戻る |
| AI提案 | 既存の提案は気づき編集だけでは削除しない |
| AI再生成 | 気づき変更後に必要に応じて案内。自動再生成はしない |

## 6. 編集の動作

1. 「編集する」を押すと、現在の本文が入力欄に入った状態で編集モードへ切り替わる。
2. 入力中は文字数カウンターを更新する。
3. 前後の空白を除去して空文字になる場合は保存不可とする。
4. **2,000文字を超える場合は保存不可**とし、超過メッセージを表示する。
5. 保存中はローディング表示を行い、二重送信を防止する。
6. 保存成功後は通常表示へ戻り、更新後の本文を表示する。
7. 保存失敗時は入力を保持し、再試行できるようにする。
8. キャンセル時に未保存の変更がある場合は破棄確認を表示する。

### 文字数超過の例

```text
気づき本文 *
┌──────────────────────────────┐
│ 編集中の本文...             │
└──────────────────────────────┘
2,015 / 2,000文字
気づき本文は2,000文字以内で入力してください。

[変更を保存]  ← 保存不可
```

## 7. 削除の動作

```text
┌──────────────────────────────────┐
│ この気づきを削除しますか？       │
│                                  │
│ 削除した気づきは元に戻せません。 │
│                                  │
│ [キャンセル] [削除する]         │
└──────────────────────────────────┘
```

- キャンセルした場合は削除しない。
- 削除成功後は書籍別の気づき一覧へ戻る。
- 削除失敗時は詳細画面に残り、エラーを表示する。
- 紐づくAI提案の削除方法・整合性はバックエンドで確認する。

## 8. AI提案との関係

- AI提案が未生成なら「AI提案を生成」を表示する。
- AI提案が保存済みなら「AI提案を見る」を表示する。
- 気づきを編集しても保存済みAI提案は残す。
- 前回AI提案生成時から気づき本文が変わった場合は、古い内容をもとにした提案である可能性を案内し、必要なら手動再生成を促す。
- 再生成は自動では行わない。
- AI提案の新規生成・再生成には、**1ユーザーあたり日本時間の1日5回**の上限を適用する。詳細は`ai-suggestion.md`を参照する。

## 9. 画面遷移

```text
書籍別の気づき一覧
       │
       ▼
   気づき詳細
       │
       ├── [編集する] → インライン編集
       │                     │
       │                     ├── 保存成功 → 詳細表示
       │                     └── キャンセル → 詳細表示
       │
       ├── [削除する] → 確認 → 削除成功 → 書籍別一覧
       │
       ├── [AI提案を見る／生成する] → AI提案画面・生成フロー
       │
       └── [戻る] → 書籍別の気づき一覧
```

## 10. バックエンド対応

- 更新時のPydanticスキーマ`InsightUpdate`にも`max_length=2000`を追加する。
- 既存の`min_length=1`および前後空白の除去を維持する。

```python
class InsightUpdate(BaseModel):
    model_config = ConfigDict(str_strip_whitespace=True)
    content: str = Field(min_length=1, max_length=2000)
```

- フロントエンドだけでなくAPI側でも2,000文字を超える更新を拒否する。
- 現在のバックエンドには最大文字数の制限がないため、**追加実装が必要**。
- `Insight`モデルの`created_at`が未実装の場合、登録日表示に向けた追加実装が必要。
- 気づき本文と保存済みAI提案の生成時本文を比較する鮮度判定も、実装方法の検討が必要。
- 既存の2,000文字超データは、閲覧・編集時にデータが失われないよう移行方針を検討する。

## 11. 確定事項と未実装事項

### 確定事項

- 詳細画面で本文全文を表示する。
- 編集は別画面ではなくインラインで行う。
- 新規登録・編集の双方で本文最大2,000文字とする。
- 空白だけの本文は保存できない。
- 編集中に文字数カウンターを表示する。
- 気づき編集では保存済みAI提案を削除しない。
- 再生成はユーザー操作時のみ実行する。

### 実装時の確認事項

- 作成日時の保存・表示
- 文字数のUnicode判定の統一
- 既存の2,000文字超データの扱い
- AI提案の鮮度判定
- 削除時の関連データの整合性
