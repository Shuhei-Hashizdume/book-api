# ユーザー新規登録画面 設計書

- 保存先：`docs/design/screens/signup.md`
- 画面名：新規登録
- 設計状態：主要仕様確定
- 対象：未ログインユーザー
- 前画面：ウェルカム画面
- 登録成功後：ホーム画面

## 1. 画面の目的

初めてBookAPPを利用するユーザーがアカウントを作成する画面。

登録時にユーザー属性を取得し、書籍から得た気づきに対するAI提案を、そのユーザーの立場に合わせてパーソナライズできるようにする。

## 2. 登録項目

| 項目           | 必須 | 入力形式       |
| -------------- | ---- | -------------- |
| ユーザー名     | 必須 | テキスト       |
| メールアドレス | 必須 | メールアドレス |
| パスワード     | 必須 | パスワード     |
| ユーザー属性   | 必須 | 1つだけ選択    |

パスワード確認欄は設置しない。

## 5. ユーザー属性

登録時に以下の8種類から必ず1つ選択する。

1. 小学生
2. 中学生
3. 高校生
4. 大学生・大学院生
5. 専門学校生
6. 社会人
7. 主婦・主夫
8. その他

### 選択時の表示


- 初期値は未選択。
- 選択した属性をフォームに表示する。
- 複数選択はできない。
- 自由入力欄は設けない。
- 「その他」を選択しても追加の入力は求めない。

## 6. 入力チェック

### ユーザー名

- 必須。
- 現行APIに合わせて1〜50文字。
- 空白文字を含めない。

### メールアドレス

- 必須。
- メールアドレス形式を確認する。
- 現行APIに合わせて最大255文字。

### パスワード

- 必須。
- 現行APIに合わせて8〜128文字。
- 目のアイコンで表示・非表示を切り替えられる。
- 確認用パスワード欄は設置しない。

### ユーザー属性

- 必須。
- 定義された8種類以外の値は受け付けない。
- 未選択の場合は「属性を選択してください」と表示する。

## 7. 新規登録時の動作

1. ユーザーが4項目を入力・選択する。
2. 「新規登録」を押す。
3. 入力内容を検証する。
4. 登録APIへ情報を送信する。
5. 登録成功後、ログイン状態を確立する。
6. ホーム画面へ移動する。

### 登録中

- 登録ボタンを無効化する。
- 処理中であることを表示する。
- 二重送信を防ぐ。

### 登録失敗時

- 入力済みの内容と選択属性を保持する。
- エラー内容を表示する。
- 同じメールアドレスやユーザー名が登録済みの場合は、その旨を表示する。

## 8. 登録後の属性変更

ユーザー属性は新規登録後も変更できる。

変更場所：

`マイページ → プロフィール編集 → ユーザー属性`

変更時も同じ8種類から1つだけ選択する。

### AI提案との関係

- AI提案の新規生成・再生成では、その時点のユーザー属性を使用する。
- 属性変更だけで保存済みAI提案を削除しない。
- 属性変更だけでAI提案を自動再生成しない。
- 保存済みAI提案が現在の属性に対応しているかを表示する仕組みは、AI提案画面側の設計で検討する。

## 9. 属性の利用目的と公開範囲

ユーザー属性は、AIが実生活での活用方法や具体的な行動を提案する際の参考情報として使用する。

例：

```text
書籍：習慣を変える本

気づき：
毎日少しずつ継続することが大切。

ユーザー属性：
大学生・大学院生
```

この場合、AIは大学生に適した行動を提案できる。

ただし、ユーザー属性だけで実際の生活状況を断定しない。

ユーザー属性は他ユーザーに公開しない。

## 10. バックエンド変更事項

現行GitHubコードにはユーザー属性が存在しないため、追加実装が必要。

### Userモデル

- 属性を保存するカラムを追加する。
- 定義された8種類の値を管理する。
- 既存ユーザーの属性をどう初期設定するか検討する。

### 登録API

`POST /users`

- リクエストにユーザー属性を追加する。
- 属性を検証する。
- ユーザーテーブルに保存する。

### ユーザー情報取得API

`GET /users/me`

- プロフィール編集に必要な属性情報を取得できるようにする。
- 属性を他ユーザー向けの公開レスポンスへ無条件に追加しない。

### 属性更新API

- 認証済みユーザーが自分の属性を更新できるAPIを追加する。
- 更新可能な値は定義済みの8種類に制限する。

### AI提案生成処理

`services/ai_suggestion.py`

- 対象の気づきを所有するユーザーの属性を取得する。
- 書籍名・著者・気づき本文とともに属性をAIへ渡す。
- 属性に適した実行可能な提案を求める。
- 属性から個別の生活事情を決めつけないよう指示する。

### データベース

- Alembicでユーザー属性カラムを追加する。
- 既存ユーザーのデータを保持したまま移行する。
- 既存ユーザーの属性未設定状態への対応を検討する。

## 12. 確定事項

- 登録項目はユーザー名・メールアドレス・パスワード・属性。
- 属性は8種類から1つだけ選択する。
- 属性は新規登録時に必須。
- 属性の自由入力はしない。
- 属性はマイページから変更できる。
- 属性はAI提案のパーソナライズに利用する。
- 属性は他ユーザーには公開しない。
- 属性変更後に生成するAI提案は新しい属性を使用する。
- 保存済みAI提案は属性変更だけでは削除・再生成しない。
- パスワード確認欄は設けない。
- PC版・スマホ版に対応する。

## 13. 実装時の検討事項

- 属性のEnum値の命名
- 既存ユーザーの属性初期値と移行方法
- プロフィール編集APIの具体的な設計
- 登録直後の認証状態を確立する実装
- 属性変更後にAI提案が古くなったことを判定する仕組み
- 未成年ユーザーを対象に含めることに伴う利用規約・プライバシー・安全設計

既存のコードにない機能は、実装済みとして扱わないこと。
