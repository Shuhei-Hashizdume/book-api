# 書籍別気づき一覧画面 設計書

- 保存先：`docs/design/screens/book-insights.md`
- 画面名：書籍別気づき一覧
- 設計状態：主要仕様確定
- 対象：ログイン済みユーザー
- 前画面：`insights.md`
- 関連画面：気づき詳細画面、気づき登録画面

## 1. 画面の目的

ユーザーが特定の書籍について登録した気づきを、一覧で振り返れるようにする。

気づき一覧画面で書籍を選択すると、その書籍に紐づく気づきだけを表示する。

この画面から、新しい気づきの登録や、既存の気づきの詳細確認へ進めるようにする。

## 2. 基本仕様

- 選択した書籍のタイトル・著者・表紙を表示する。
- その書籍に登録された気づきの総件数を表示する。
- ログイン中のユーザー自身が登録した気づきだけを表示する。
- 気づきは登録日時が新しい順に並べる。
- 各気づきをカード形式で表示する。
- カードには気づき本文のプレビューを表示する。
- 気づきカードを選択すると気づき詳細画面へ移動する。
- 「＋ 気づきを追加」ボタンを設置する。
- 追加ボタンを押すと、現在の書籍が選択された状態で気づき登録画面へ移動する。
- 「気づき一覧に戻る」操作を用意する。
- AI提案の全文は本画面には表示しない。

## 5. 気づきカードの表示内容

各カードには次の情報を表示する。

| 項目       | 内容                       |
| ---------- | -------------------------- |
| 気づき本文 | 登録された本文のプレビュー |
| 登録日     | 気づきを新規登録した日     |
| 遷移表示   | 詳細画面へ進める矢印       |

### 本文プレビューの扱い

- 本文の冒頭部分を表示する。
- 長い本文は一定行数で省略する。
- 本文全文は気づき詳細画面で表示する。
- ユーザーが入力していないタイトルを自動的に生成して保存することはしない。

ワイヤーフレームに記載した「継続することの大切さ」などの見出しは表示例であり、実際には本文の冒頭を見出しのように見せる。

### 登録日の扱い

- 登録日時をもとに日付を表示する。
- 表示形式は `YYYY/MM/DD` とする。
- 気づきを編集しても登録日は変更しない。

## 6. 気づきの並び順

登録日時の新しい順とする。

```text
2026/10/20 登録した気づき
2026/10/18 登録した気づき
2026/10/15 登録した気づき
```

新しい気づきを登録した場合は、一覧の先頭に表示する。

既存の気づきを編集しただけでは、並び順を変更しない。

同じ登録日時の気づきが複数ある場合は、IDの降順を補助的な並び順として使用する案を採用する。

## 7. 気づき追加ボタン

表示文言：

`＋ 気づきを追加`

### 押したときの動作

1. 現在表示している書籍のIDを引き継ぐ。
2. 気づき登録画面へ移動する。
3. 登録画面では対象書籍をあらかじめ設定する。
4. 登録成功後は、対象書籍の気づき一覧へ戻る。
5. 新しく登録した気づきを一覧の先頭に表示する。
6. 気づき件数を更新する。

気づき登録画面そのものの入力項目・操作仕様は別の設計書で定義する。

## 8. 気づきが0件になった場合

この画面を開いている間に最後の気づきが削除されるなど、書籍の気づき件数が0件になる場合がある。

その場合は次の表示とする。

```text
┌──────────────────────────────┐
│ ← 気づき一覧に戻る           │
│                              │
│ Python入門                   │
│ 気づき：0件                  │
│                              │
│ まだこの本の気づきは         │
│ 登録されていません。         │
│                              │
│ [ ＋ 気づきを追加 ]          │
└──────────────────────────────┘
```

- 気づきカードは表示しない。
- 対象書籍への気づき追加は可能にする。
- 気づき一覧画面に戻った場合、気づき0件の書籍は表示しない。

## 10. データ取得中・エラー時

### データ取得中

- 書籍情報と気づき一覧を読み込んでいることが分かる表示にする。
- 読み込みが完了するまで、気づき0件の案内を表示しない。

### データ取得失敗

- 「気づきを読み込めませんでした。」と表示する。
- 「再試行」ボタンを設置する。

### 対象書籍が存在しない場合

- 「書籍が見つかりません。」と表示する。
- 本棚または気づき一覧に戻れるようにする。

### 他人の気づきへのアクセス

- 自分以外のユーザーが登録した気づきは表示しない。
- バックエンド側でもログインユーザーに紐づくデータに限定する。

## 11. バックエンドとの対応

GitHubで確認した気づきAPI：

```http
GET /users/me/books/{book_id}/insights
POST /users/me/books/{book_id}/insights
PATCH /users/me/books/{book_id}/insights/{insight_id}
DELETE /users/me/books/{book_id}/insights/{insight_id}
```

### 現行実装との違い

現行の `routers/insights.py` では、気づき一覧を `Insight.id` の昇順で取得している。

今回の画面仕様では、登録日時の降順が必要となる。

また、確認した `InsightResponse` には次の項目がある。

```text
id
content
book_id
book_title
```

登録日時はレスポンスに含まれていない。

そのため、実装時には以下を確認・対応する必要がある。

- `Insight` に登録日時を保存するフィールドがあるか。
- なければ `created_at` の追加を検討する。
- APIレスポンスで登録日時を返す。
- 新しい気づきから取得するようにする。
- 書籍の著者・表紙を取得する。
- 書籍ごとの気づき件数を表示する。

**重要：画面仕様が確定していても、バックエンドがすべて対応済みとは限らない。**

必要な変更は実装段階で確認する。

## 12. AI提案機能との関係

BookAPPでは、ユーザーが登録した気づきをもとにAIが次の4項目を生成する。

1. 気づきの整理
2. 気づきの深掘り
3. 実生活への活用方法
4. 次の具体的な行動

ただし、本画面はあくまで気づきを一覧表示する画面とする。

AI提案の生成・表示・再生成は、気づき詳細画面から進む別画面で扱う想定とする。

AI提案画面に再生成ボタンを設置する案は、今後のAI提案画面設計で検討する。

## 13. 確定事項と今後の検討事項

### 確定事項

- 選択した書籍の気づきを一覧表示する。
- 書籍の表紙・タイトル・著者・気づき件数を表示する。
- 気づきを新しい登録日時順に並べる。
- 「＋ 気づきを追加」ボタンを設置する。
- 気づきカードを選択すると気づき詳細画面へ移動する。
- 気づき一覧へ戻れるようにする。
- PC版・スマホ版の両方に対応する。

### 画面設計上の提案・実装時確認事項

- 気づきカードの本文プレビュー行数
- 登録日の表示形式
- 気づき0件になった場合の表示
- 同一登録日時の場合の補助的な並び順
- 気づき登録成功後の遷移
- 大量の気づきがある場合のページ分割
- 登録日時を保存・返却するためのDB/API変更
- 気づき詳細画面とAI提案画面の具体的な構成

未確定の項目は、実装時に勝手に確定扱いしないこと。
